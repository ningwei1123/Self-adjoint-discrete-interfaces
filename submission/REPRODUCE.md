# Reproduction manifest

Every number and figure in the manuscript is regenerated by one of the scripts below.
Each script prints its own tables and writes a plain-text record into `results/`; those
records are what the manuscript quotes, which is why `results/` ships with the code.

Run every command **from the repository root**.

## A full run

```bash
python -m pip install -r requirements.txt

# the interface operator and the two transfer pairings
python src/coupled_solver.py
python src/coupled_solver3d.py
python src/coupled_solver3d_mortar.py

# the matching law and its conditions
python src/theory_energy_matching.py
python src/verify_p2_claim.py

# the remaining sections
python src/m2_iterative.py
python src/multi_interface.py
python src/patch_independent.py
python src/stress_recovery2d.py
python src/stress_recovery3d.py
python src/lame_cylinder.py
python src/nonlinear_2d_final.py
python src/annulus_benchmark.py
python src/func_operator.py
python src/cost_report.py
python src/train_stats_cost.py

# the figures
for n in 1 2 3 4 5 6 7 8 9; do python scripts/figure_$n.py; done

# the manuscript
cd paper && tectonic -X compile main.tex    # or pdflatex + bibtex
```

## Two honest caveats

1. `scripts/fig06_upgrade.py` and `scripts/fig08_upgrade.py` carry a few published
   constants (`LIN`, `DN_ENS`, `DN_M`, `DN_S`) instead of reading them from a record.
   Figures 6 and 8 therefore **render** the reported values but do not **recompute**
   them; the values come from `src/coupled_solver3d_mortar.py`,
   `src/func_operator.py` and `src/train_stats_cost.py`.

2. The deep-learning results are non-deterministic across hardware. The seeds are fixed
   and listed in the README, and the reported accuracy is an ensemble property, so
   exact agreement with the manuscript is expected only for the ensemble mean.

## Author input required

archive DOI. They are mirrored in `README.md`, `CITATION.cff` and `.zenodo.json`.
